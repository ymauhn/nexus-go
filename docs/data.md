# Data

Nothing in `data/` is version-controlled — the corpus is about 474 MB, and the derived
`raw/` embedding cache is several gigabytes. This document records where each piece comes
from so the experiments can be reconstructed.

## Annotation corpus

Derived from the **CAFA5** (Critical Assessment of Protein Function Annotation, 5th
edition) training corpus. The official test ground truth was not publicly released, so the
splits used here were derived from the competition's training data — they are **not** the
official CAFA5 benchmark, and results are not directly comparable to the CAFA5 leaderboard.

Splits are ~80/10/10, disjoint at the protein level, built independently per ontology
(only proteins carrying at least one annotation in that ontology):

| Ontology | Train | Validation | Test | GO terms |
|---|--:|--:|--:|--:|
| Biological Process | 73,768 | 9,221 | 9,221 | 500 |
| Cellular Component | 74,328 | 9,292 | 9,292 | 498 |
| Molecular Function | 62,909 | 7,864 | 7,864 | 499 |

Label density in the training split: 5.18% (BP), 2.51% (CC), 1.51% (MF).

## Interaction network

**STRING v11.5**. The combined score is an integer in [1, 1000], divided by 1000 and
filtered at the medium-confidence threshold of 0.400, giving observed scores in
[0.400, 0.999]. The file arrives already mapped to UniProt accessions: 2,422,234 records
describing 791,011 distinct pairs after deduplication by pair (maximum score) and removal
of self-loops.

Roughly a third of the proteins in each corpus retain no interaction at this threshold —
the structural ceiling that a topology-only predictor cannot cross, and the reason the
hybrid formulation exists.

## Ontology

Gene Ontology, from the OBO release shipped with the consolidated dataset. Obsolete terms
are discarded and `alt_id` entries are mapped to their canonical term. Parsing, ancestor
closure over `is_a`, and true-path-rule propagation of predictions are implemented in
`ppi_v4/ppi_v4/metrics.py`.

## Sequence embeddings

**ProtT5-XL-U50** (`Rostlab/prot_t5_xl_half_uniref50-enc`), used frozen.

`prot_t5.py` loads the model by name, without a `revision=` argument, so the version is not
recorded at run time. It is established here from two facts that pin it unambiguously: the
embeddings under `raw/` were generated on **2025-11-24/25**, and the model repository's most
recent commit is **2023-01-31**. Any download in that window resolves to the same revision,
which is still the head of `main`.

That 2023-01-31 commit only edited the README. The weights were uploaded on 2022-05-20
(`e380a835582c6ed7bb93fbeaeba500174d9a5b54`) and the configuration last changed on
2022-05-21 (`f94c9e6bb5c077ccd6fe1a34e7d1a0400aeb9a39`), so the artefacts these results
depend on have not moved since May 2022 — whichever of the three revisions is cited.

To pin it explicitly in future runs:

```python
T5EncoderModel.from_pretrained(
    "Rostlab/prot_t5_xl_half_uniref50-enc",
    revision="94a6abc029ae13029317b140b7424e012bf8dfbf",
    torch_dtype=dtype,
)
```

To verify a local copy against the published hash:

```bash
sha256sum ~/.cache/huggingface/hub/models--Rostlab--prot_t5_xl_half_uniref50-enc/snapshots/94a6abc029ae13029317b140b7424e012bf8dfbf/pytorch_model.bin
# expected: 7f51ba885541c7dc569d46b796af57cc7a2ba7945107dced4f19d1b5ec091157
```

Sequences longer
than 1,022 tokens are chunked; layers 24, 23 and 22 are read, mean-pooled over valid
positions using the attention mask, and concatenated into a 3,072-dimensional vector per
protein.

Generated by `ppi_v4/ppi_v4/extract_raw.py` into `raw/raw_{bp,cc,mf}/`, three files of
1,024 floats per protein. At roughly 74k proteins per ontology this is about 220,000 files
and ~900 MB per domain — ignored in git for the file count as much as the size.

## Obtaining the data

Nothing here is downloadable by a single script — two of the three sources require
registration or a large manual download. The steps:

**1. CAFA5 corpus.** From the Kaggle competition
`kaggle.com/competitions/cafa-5-protein-function-prediction` (accepting the rules is
required). With the Kaggle CLI configured:

```bash
kaggle competitions download -c cafa-5-protein-function-prediction -p data/raw_download
```

The splits used here are not the competition's own — they were derived from its training
corpus, disjoint at the protein level, ~80/10/10 per ontology. The consolidated split files
came from the group's earlier SUPERMAGO/SUPERMAGOv2 line; ask the authors for
`{bp,cc,mf}_{train,val,test}.csv` and `{bp,cc,mf}_ic.csv`, or rebuild them from the raw
corpus with the same protocol.

**2. STRING v11.5 interactions.**

```bash
wget https://stringdb-downloads.org/download/protein.links.v11.5.txt.gz
```

Map identifiers to UniProt accessions, keep `combined_score >= 400`, divide by 1000,
deduplicate by pair taking the maximum, and drop self-loops. The resulting `data/ppi.csv`
has three columns: `protein_A, protein_B, score`.

**3. Gene Ontology.**

```bash
wget http://purl.obolibrary.org/obo/go.obo -O data/go.obo
```

**4. ProtT5 embeddings** (needed only by the second generation). Generated locally, not
downloaded:

```bash
cd ppi_v4
python -m ppi_v4.extract_raw --domain bp   # repeat for cc and mf
```

This writes `raw/raw_{domain}/{PID}-{22,23,24}.npy`, roughly 220,000 files and ~900 MB per
ontology. Expect this to take hours on a single GPU.

## Where the code looks for it

The two generations run from different working directories, and each expects its data
alongside:

| Generation | Working directory | Expects |
|---|---|---|
| `ppi_only` | repository root | `data/` (or pass `--data-dir`) |
| `ppi_v4` | `ppi_v4/` | `ppi_v4/data/` and `ppi_v4/raw/` |

The usual arrangement is a symlink in each place pointing at one shared copy:

```bash
ln -s /path/to/data data
ln -s /path/to/data ppi_v4/data
ln -s /path/to/raw  ppi_v4/raw
```

Both symlinks are ignored by git.
